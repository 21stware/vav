# VAV product matrix

Seven products, one control plane. Turns, keys, files, and PTYs live in **vavd**.
Every other product is a shell over that daemon.

| Product | Role | Talks to vavd as |
| --- | --- | --- |
| **vavd** | Core service. Sessions, secrets, files, PTY, agent turns. | — |
| **vav-desktop** | Local workbench (`packages/vav-desktop/src`). Same UI for a local vavd and a paired remote. In-process PTY restore is off when this window is a shell over vavd. | `phone` + `daemon` |
| **vav-cli** (`vavcli`) | Claude Code-style agent CLI: TTY REPL that prints the host reply, `-p`, JSON, RPC (`prompt` / `reply` / `edit` / `continue` / `quit`), slash commands (TTY or one-shot `vavcli /files` / `/file` (`mkdir` / `rename` / `rm` / `exists`) / `/review` / `/git init` / `/github` (`pulls` / `pull` / `actions` / `run` / `releases` / `pages`) / `/timers` (`list` / `create` / `add` / `get` / `update` / `run` / `remove` / `runs` / `sessions`) / `/plugins` / `/connectors` (`auth` / `probe` / `status` / `act`) / `/logs` (`query` / `stats` / `clear` / `export` / `record` / `tail`) / `/file-session` (`open` / `create` / `list` / `activate` / `rename` / `delete` / `force-delete` / `readonly`) / `/pin` / `/star` / `/archive` / `/stop`). | `phone` + `daemon` |
| **vavc** | Herdr-style control client: session / workspace / agent / file (`list` / `stat` / `read` / `write` / `mkdir` / `rename` / `rm` / `exists` / `reveal` / `open` / `info`) / file-session (`open` / `create` / `list` / `activate` / `rename` / `delete` / `force-delete` / `readonly`) / pane (`run` / `spawn` / `write` / `kill`) / review / account (`oauth` / `cancel` / `signout` / `update` / `current` / `activate` / `verify` / `reveal`) / connectors (`auth` / `probe` / `status` / `act`) / github (`pulls` / `pull` / `actions` / `run` / `releases` / `pages`) / timers (`list` / `create` / `add` / `get` / `update` / `run` / `remove` / `runs` / `sessions`) / logs (`query` / `stats` / `clear` / `export` / `record` / `tail`) / settings (`get` / `set` / `secret` / `hint` / `reveal-secret`) / `git init` / `git branch` / `git checkout` / `git worktree` / `plugins create\|enable`. | `phone` + `daemon` |
| **vav-iOS** | Native remote. Pair, list, talk, configure. | `phone` (hello omits `role`) |
| **vav-android** | Same remote as iOS, Kotlin. | `phone` (hello omits `role`) |
| **vav-chrome-extension** | Side panel. Same session shell as desktop / web. | `phone` + `daemon` over loopback or RFC1918 WebSocket |

## Alignment

- Chrome extension, local web UI, and desktop mount the same session shell (`App` + run bar). Required e2e (`e2e/specs/phone-ui.spec.ts` and `e2e/specs/chrome-extension.spec.ts`) plus web UI e2e click New bash, assert a live `pty.list` tab, and echo through the real xterm canvas (`vav-phone-term`), matching the desktop workbench terminal. The MV3 spec loads unpacked `extension/` at `chrome-extension://…/sidepanel.html` — not only the loopback web origin. Chrome / web open a second `/vav` hello as `role: 'daemon'` for Files preview, Terminal, Git (`git.status` / diff / init), Plugins (`plugins.list`), GitHub (`github.listPulls` / Actions / Releases / Pages), timers (`timers.listJobs`), connectors / vendor status (`connectors.catalog`, `connectors.beginLogin`, `cloudflare.status`, `supabase.status`, `vercel.status`), file-preview conversations (`fileSessions.open` / create / list), change review (`changeSets.get` / accept / reject), Settings → Logs (`logs.query` / stats / clear / export), Settings → Accounts (`accounts.getPage` / create / update / remove / verify / reveal / `beginOAuth` / `cancelOAuth` / `signOut`), Settings → Connect incoming (`host.pairing` / `host.rotateOffer` / `host.incoming`, QR shown because the host is already listening), and File Preview (`files.inspect` over `fs.stat` + `fs.readFile`). Compact / regenerate / edit / fork / delete-message / leaf / duplicate / continue / goal / locate use the same phone-plane verbs as desktop. Folder pick and Locate open the same remote folder picker over `hosts.listDir` (`fs.readdir`). Settings opens the desktop Settings window as an overlay (`vav:phone-open-settings`); required Chrome / web e2e opens that overlay, asserts the same `settings-nav-*` categories as desktop, writes Logs retention through `settings.update`, drafts/removes a Providers account, rotates the incoming `vavrtp://` offer, lists the same code-font candidates as desktop, opens a created file in the desktop file-preview drawer (filename + body), renames and trashes a Files tray row over `fs.rename` / `fs.unlink`, Pins / Renames a list row from the same DOM context menu as desktop, opens the Files Git / Plugins tabs after `git.init`, and mints another session row with New Session. When desktop is a shell over spawned vavd, File Preview, change-review, accounts, timers, plugins, Git / GitHub, connectors, host settings, **Files tray I/O**, **git spawn**, and **PTY** resolve through that vavd host so the workbench and Chrome share one grant plane. Appearance / fonts stay on the client (`availableFonts` uses the same `codeFonts` candidates as desktop; custom accent and surface-pattern tiles use the browser color / PNG pickers). The side panel reports the **host** OS (`darwin` / `win32` / `linux`) instead of a hardcoded Linux, so Finder / Explorer labels and Get Info menus match the workbench. Reveal in Finder, Open with default app, Quick Look, Get Info, and Copy as file call `fs.reveal` / `fs.openPath` / `fs.preview` / `fs.getInfo` / `fs.copyAsFile` on that vavd so the host file manager opens — the same commands desktop-remote and `vavc file reveal|open|info` use. Connect paste (`hosts.pair`) pairs a loopback or RFC1918 LAN `vavrtp://` (Chrome requests optional host permission for that LAN origin); WAN / Tailcat pairing stays on desktop. Legacy API / connector tokens (`settings.setSecret`) live on that same vavd secret store. Change-review Accept / Reject for a spawned workbench uses the host `changeSets.*` catalog; e2e seeds the review on vavd. Chrome Files Save / rename / trash / clip write the same `fs.writeFile` / `rename` / `unlink` verbs. The Files tray live-refreshes over `fs.watch` / `fs.unwatch` with the same 300 ms dirty-dir coalescing as desktop `FileService.watchRoot`. Clipboard image paste writes a host `vav-clips` file over `fs.writeFile`. Phone `browse` (`files: true`) remains the fallback list when the daemon plane is down. iOS / Android stay phone-only. Connector CLI login (`gh auth login` and friends) starts on the host so Chrome Settings can sign in the same way as desktop.
- iOS and Android speak the same phone-protocol verbs (`REMOTE_PHONE_CLIENT_TYPES`) and show the same run-bar order (`mode · permission`, agent/model, `thinking · Fast`). Android chips call the same `configure` keys as iOS (`mode`, `approvalMode`, `agent`, `model`, `thinkingLevel`, `fast`) and the same session actions (rename / pin / favorite / archive / temp workspace / compact / duplicate / continue / regenerate / edit / fork / goal / locate / delete-message / leaf / review, send queue, live tool blocks, 拷贝 / 展开 / 收起, 改动审查 file names + 全部接受 / 全部拒绝). Both lists show 正在连接电脑… / 正在同步会话… and the same subtitle ladder (`恢复中` / `流式中` / `刚刚 · 目录`); a leaked transport turn paints the same Recovering chrome as desktop (`turn.recovery`). Both remotes suspend the socket in the background and reconnect after 4s when foreground, keep an optimistic local send until the host thread catches up, and surface 无法新建会话 / 对话同步超时. Agent logs use the same GFM surface (headings, tables, lists, code, task lists, `withAgentLineBreaks`); the Android run bar sits in the composer like iOS / desktop (`mode · permission` then `thinking · Fast`). An offline thread shows 还没连上电脑 and 重试连接. Opening a thread marks it as the viewing conversation so a reconnect re-pulls that transcript; send / turn errors surface as 发送失败, not a link drop. The session list carries the host `goal` snapshot so both remotes paint the same 目标 banner as desktop. Settings lists host capabilities as 可以 / 仅电脑; notifications open the session and clear that conversation’s rows. Background lock-screen banners tap through to the same conversation. Both Settings screens export a redacted 诊断日志 ring (`DiagLog`) after a failed WAN dial and share the same 电脑 / 默认配置 / Host 沙盒 / 诊断 build 4 copy. Tailcat QR tokens (`tc…`) dial the same Go bridge: iOS via `TcmobileDial`, Android via `TcmobileSessions.dial` after `build-tailcat-android.mjs`. Live e2e (`phone-remote.spec.ts`) dials vavd with that same omitted-role hello and exercises every `REMOTE_PHONE_CLIENT_TYPES` verb, including parked Approve `reply` / `cancel` and change-review `get` / `accept-all`.
- Desktop local and desktop-paired-to-vavd are the same sidebar: switch the service chip, do not mint a second chat. Sessions Chrome creates on the spawned vavd adopt as local workbench rows. New Session on desktop waits for the spawned vavd pair (`waitForMountedLocalShell`) then creates on that vavd first — it does not mint an in-process row while auto-pair is still in flight. Settings → Agents binary probes for This Mac use that same vavd `probeProviders` catalog. Rename / archive / pin / delete on the workbench dial that vavd so Chrome’s list matches. Local conversation JSON lives only under the spawned vavd state dir; Electron `userData/conversations` keeps paired-remote rows, not a second local transcript. Paste clips share `tmp/vav-clips/<sha16>/name`. Desktop e2e `desktop-vavd-matrix.spec.ts` plus named-branch `launchWorkbench` specs (list / send / workspace / files-preview / terminal / stream / transcript / workdir / change-review / session sidebar / Connect tunnel / pin-archive-rename-delete / shortcuts / Settings chrome / appearance / keybindings / About / log retention / unseen Done / quote-regenerate / rich seed / swarm / boot / ACP chrome / live ACP / screenshot crop) run that spawned path. Live ACP stdio (Cursor and Grok fixtures), `configure.mode` (`session/set_mode`), usage / context ring, plan-accept, model pin, and network retry run on that vavd — the same plane iOS / Android / Chrome / `vavc configure --mode` / `vavcli /run-mode` use. After a host turn ends the workbench pulls `sessions.get` so `tokensUsed` / `cliResumeCursor` / ACP chrome match the daemon store. First-run empty (no API key) uses the same spawned vavd as production (`launchWorkbench`); the no-key hero keys off `settings.apiKeyPresent` from that host catalog, not `hostHoldsControlPlaneKeys`, so Configure an API Key still shows until a VAV account key or legacy `api` secret exists on that vavd. A workbench Providers save republishes the merged host snapshot so the hero clears the same way as in-process. A background turn on that vavd marks `resultUnseen` on the workbench the same way an in-process turn does. Web UI e2e seeds the same review over `changeSets.seedReview` and asserts the desktop `inline-review` card. The matrix asserts the stub turn lands in `userData/vavd/conversations` rather than a second Electron shard. Chrome Settings OAuth (`accounts.beginOAuth`) starts the same host CLI login the desktop Providers pane uses.

## Source

Root is an npm workspace (`packages/*`). Each product owns its entry tree.
The shared kernel (`src/main/` + `src/shared/`) stays outside the packages.

| Product | Identity | Source |
| --- | --- | --- |
| vavd | `packages/vavd/` (`@21stware/vavd`) | `packages/vavd/src/vavd.ts` (kernel: `src/main/daemon/`) |
| vav-desktop | `packages/vav-desktop/` (`@21stware/vav-desktop`) | `packages/vav-desktop/src/{main,preload,renderer}` |
| vav-cli | `packages/vav-cli/` (`@21stware/vav-cli`) | `packages/vav-cli/src/vavcli.ts` |
| vavc | `packages/vavc/` (`@21stware/vavc`) | `packages/vavc/src/vavc.ts` |
| vav-iOS | `packages/vav-ios/` | `packages/vav-ios/VAVRemote/` |
| vav-android | `packages/vav-android/` | `packages/vav-android/VAVRemote/` |
| vav-chrome-extension | `packages/vav-chrome-extension/` | `packages/vav-chrome-extension/extension/` + `phone-ui/` |

Catalog: `src/shared/productCatalog.ts`. Shared contracts: `src/shared/remoteControl.ts` (session plane), `src/shared/daemonProtocol.ts` (fs / pty).
